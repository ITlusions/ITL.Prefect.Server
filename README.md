# ITL Prefect Server

Helm wrapper around the upstream `prefect-server` chart, deployed to the `itl` cluster with Argo CD.

- **URL:** https://prefect.dev.itlusions.com (API under `/api`, UI at `/`)
- **Namespace:** `prefect`
- **Argo CD app:** `prefect-server` (manual sync, tracks `main`)
- **Prefect version:** 3.8.8 (`prefect-server` chart 2026.10.6163015)

## What runs

| Component | Kind | Notes |
|---|---|---|
| `prefect-server` | Deployment, 1 replica | Prefect API and UI, port 4200 |
| `prefect-server` | Service, ClusterIP | Only reachable through the ingress |
| `prefect-server` | Ingress (Traefik) | TLS via cert-manager, `letsencrypt-issuer` |
| `prefect-postgres` | Deployment, Service | Postgres 17, `emptyDir` storage (not persistent) |
| `prefect-server-postgres-bootstrap` | Job (pre-sync) | Creates the generated Secrets, only if missing |
| `prefect-server-work-pools` | Job (post-sync) | Creates the `itl-amalia` Kubernetes work pool |

The Service is `ClusterIP`. The former LoadBalancer on the LAN is removed, so the ingress is the only entry point.

## Secrets

Both credentials are generated by the bootstrap Job. Nothing secret is stored in git.

| Secret | Keys | Used by |
|---|---|---|
| `prefect-postgres` | `password`, `connection-string` | Postgres, the server |
| `prefect-server-basic-auth` | `username`, `auth-string` | the server (`PREFECT_SERVER_API_AUTH_STRING`), the work-pool Job (`PREFECT_API_AUTH_STRING`) |

- The Job creates a Secret only if it doesn't exist, so values stay stable across syncs.
- The basic-auth username is `admin-` plus 8 random characters. The password is 32 random characters.
- To read the credentials:
  ```
  kubectl --context itl -n prefect get secret prefect-server-basic-auth -o jsonpath='{.data.username}' | base64 -d
  kubectl --context itl -n prefect get secret prefect-server-basic-auth -o jsonpath='{.data.auth-string}' | base64 -d
  ```
- **Rotate:** delete `prefect-server-basic-auth`, then sync. Update every client afterwards (the worker, CLI users).

## Authentication

- The API requires HTTP Basic auth. Requests without valid credentials get `401`.
- Health and ready probes are exempt (`/api/health`, `/ready`).
- This is one shared login. There are no per-user accounts or roles.

Clients set:

```
PREFECT_API_URL=https://prefect.dev.itlusions.com/api
PREFECT_API_AUTH_STRING=<auth-string value>
```

Inside the cluster, use the service URL `http://prefect-server.prefect.svc.cluster.local:4200/api`.

## Deploying

1. Change values or templates in this repo.
2. Commit and push to `main`. Argo CD reads `main`.
3. Refresh and sync the `prefect-server` app in the Argo CD UI, or:
   ```
   kubectl --context itl -n argocd annotate application prefect-server argocd.argoproj.io/refresh=hard --overwrite
   ```
4. Watch the rollout:
   ```
   kubectl --context itl -n prefect get pods,jobs,ingress,certificate
   kubectl --context itl -n argocd get application prefect-server
   ```

The sync is manual on purpose. Nothing deploys until someone syncs.

### Verify after a sync

```
curl -s -o /dev/null -w "%{http_code}\n" https://prefect.dev.itlusions.com/api/health        # 200
curl -s -o /dev/null -w "%{http_code}\n" -X POST https://prefect.dev.itlusions.com/api/flows/filter -H 'Content-Type: application/json' -d '{}'   # 401 without credentials
```

## Work pools

The chart creates the `itl-amalia` pool of type `kubernetes`, which is where the worker picks up runs. The `work-pools` Job uses the basic-auth credential, so it needs the Secret to exist first.

The worker itself is a separate chart (`ITL.Prefect.Worker`). It isn't deployed yet. Once deployed, it needs `PREFECT_API_AUTH_STRING` set to the `auth-string` value.

## Known limitations

- **Postgres storage is `emptyDir`.** Data is lost when the pod restarts. Turning on `postgres.persistence` and moving to CloudNativePG would fix this.
- **Basic auth only.** There's no SSO. An OIDC design (Keycloak, oauth2-proxy or a plugin) is under discussion.
- **Network policy isn't enforced by the cluster's flannel CNI.** Any NetworkPolicy objects won't limit traffic until that's changed.
- **Startup race.** The server can crash once if it starts before Postgres accepts connections. Restarting the deployment fixes it.
- **Demo labels.** `commonLabels` still says `environment: "demo"`.
- **Upstream image tag.** The Helm chart pins Prefect 3.8.8, and the bootstrap image `alpine/k8s:1.31.4` is pinned by tag, not digest.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Server pod `CrashLoopBackOff`, `ConnectionRefusedError` on 5432 | Postgres wasn't ready. Restart the deployment: `kubectl -n prefect rollout restart deploy/prefect-server` |
| Work-pools Job `Error`, `401 Unauthorized` | The Job lacks `PREFECT_API_AUTH_STRING`, or the Secret is missing |
| Argo CD shows `OutOfSync` after sync, hook never completes | A stale hook Job from an earlier sync. Delete the Job and sync again |
| Certificate stays `False` | Check `kubectl -n prefect get challenge`. HTTP-01 needs port 80 reachable on the ingress IP |
| `401` in the browser UI | Expected, since basic auth is on. The UI has no login prompt yet |
